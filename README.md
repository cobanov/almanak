X hands over your posting history as a folder of JavaScript files nobody can
read. almanak turns it into a timeline you drag through, a gallery of every
photo, threads rebuilt into something readable, and analysis that states its
own denominators.

It runs entirely in your browser. There is no backend, so there is nowhere for
your archive to go.

## What it does

- **Timeline** — a density track you drag through the archive, with momentum
  and zoom from year to day. A panel reports what the selected period was
  like: how much was posted and of what kind, what it collected, its most
  liked tweet, and whether it was busier than the period before. Silences are
  drawn on the track, and an empty stretch says how long you were quiet.
- **Search** — instant, with `"exact phrase"`, `-exclude`, `from:2023` and
  `has:media`, plus composable filters for kind, media, client, language,
  weekday, hour and date range. Every filter round-trips through the URL.
- **Threads** — self-replies rebuilt into single pieces with a spine, word
  count and reading time. Copy one out as a markdown document.
- **Gallery** — justified rows at each image's own proportions, never cropped
  square, with year and type filters and a link back to the tweet that carried
  it. And a shuffle, which is the closest thing to rediscovering them.
- **Analysis** — rhythm punchcard with a timezone selector, client
  archaeology, vocabulary drift, your orbit, reply ratio, the gaps, nocturnal
  index, firsts. Every figure clicks through to the tweets behind it.
- **Export** — JSON, CSV, Markdown, and a print-resolution poster with one
  mark per tweet.

## Turkish

Search folds the dotted and dotless i together and peels stacked suffixes, so
`model` finds `modelleri` and `isik` finds `IŞIK`. This matters more than it
sounds: general Unicode case folding gets Turkish `I` and `İ` wrong in
opposite directions, and Turkish stacks suffixes, so a stemmer that peels one
splits a single concept across several entries in every term count.

It is a shallow normaliser, not a morphological analyser, and it says so where
the output is shown.

## Privacy

- **No uploads.** There is no backend. Your export is opened by the browser,
  from your disk, and read there.
- **Direct messages are never read.** `src/archive/dm-guard.ts` decides every
  path the app opens, with an allowlist plus a forbidden-substring backstop,
  and a test suite keeps it honest.
- **No analytics, no telemetry, no cookies.**
- **The build fails on a stray request.** `scripts/check-network.ts` rejects
  any `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon` or hard-coded
  remote host outside two allowlisted modules.
- **Delete everything** clears IndexedDB, OPFS, cache storage, local storage
  and service workers, and reports which of those actually succeeded rather
  than claiming success.

## Measured

Numbers from a real machine, not estimates. Reproduce them with the harness:

```bash
npm run harness -- /path/to/archive "search term"
```

| Operation | Budget | Measured |
|---|---|---|
| Parse 200,000 tweets (181 MB) | < 20 s | **2.3 s** |
| Parse a 10,000-tweet archive (20 MB) | < 2 s | **152 ms** |
| Search, 200k archive, worst case | < 60 ms | **37 ms** |
| Search, 10k archive | < 60 ms | **0.8–2 ms** |
| Timeline track paint, 6,000 buckets | < 16.7 ms | **1.39 ms** |
| Production bundle | — | **~90 kB** gzipped, fonts self-hosted |

Generate an archive at the pathological size yourself:

```bash
node scripts/make-stress-archive.ts /tmp/stress 200000
npm run harness -- /tmp/stress
```

## The format

X's export is not what its documentation suggests, and it has changed quietly.
[`docs/ARCHIVE-FORMAT.md`](docs/ARCHIVE-FORMAT.md) is generated by reading a
real archive rather than from memory:

```bash
npm run inspect -- /path/to/archive
```

Three traps that silently corrupt anything built on this data:

- **Entity offsets count codepoints, not UTF-16 units.** JavaScript strings
  are UTF-16, so slicing a tweet by X's own offsets returns the wrong span for
  every tweet with an emoji before a mention.
- **An edited tweet is stored once per revision**, each with its own id, and
  only the newest carries real engagement. One reference archive's 10,130
  records are 10,090 distinct tweets.
- **Video filenames use a URL hash where photos use a media id**, so joining
  media by id fails for every video.

## Running it

```bash
npm install          # Node 22.6+
npm run dev          # the app at http://localhost:5173/app/
npm test             # parser and store suites
npm run build        # landing at /, app at /app/, into dist/
```

The build produces one static site: the landing page at the root and the app
under `/app/`. They share an origin, which is what lets the landing page embed
the real application in its hero rather than a recording.

### Deploying

Any static host works, and paths are relative, so it runs from a domain root
or a subdirectory such as a GitHub Pages project site.

One requirement is not negotiable: **serve it over HTTPS.** The import flow
uses the File System Access API, and service workers and OPFS have the same
rule — all three are gated on a secure context. Over plain `http://` the page
loads and then cannot open a folder, which reads as a bug in the app.

```bash
npm run deploy       # Cloudflare Pages, via wrangler
```

`_headers` and `_redirects` ship in `dist/` for hosts that read them; the
headers include a Content-Security-Policy that enforces the no-network claim
rather than asking you to believe it.

Visitors need Chrome or Edge to pick a folder — Firefox and Safari have not
shipped the File System Access API. Those browsers fall back to dropping the
ZIP, which works everywhere, and the import screen says so rather than failing
silently.

## Testing

```bash
npm test                               # 72 tests
npm run fixtures -- /path/to/archive   # rebuild the redacted fixture archive
npm run demo:archive                   # regenerate the invented demo archive
npm run check:network                  # fail on any stray request
```

`fixtures/archive/` is a complete miniature export with the same directory
layout as a real one, built from a real archive and redacted by substituting
each letter within its own alphabet — so Turkish text stays Turkish and still
exercises dotted and dotless i while carrying no meaning. See
[`fixtures/CASES.md`](fixtures/CASES.md).

The demo archive is invented rather than redacted: a fictional account with
eight years of plausible posting, so every panel has something real to show.

## Known limits

- **Note-tweet stitching and pre-2020 archives are untested.** No archive we
  have seen contains either, so those paths ship unverified and say so in the
  import summary. A test archive would fix this.
- **Turkish term statistics are approximate.** The normaliser is not a
  morphological analyser, so vocabulary drift and era labels are weaker than
  the English equivalent. They are shown as inferred for that reason.
- **Likes and retweets are as of the export date**, not live.
- **Retweet text is stored cut off** by X and cannot be recovered.
- **A reply's parent is not in the archive.** Roughly 60% of a typical archive
  is one side of a conversation; the app draws the missing half as a labelled
  gap rather than pretending the fragment stands alone.
